# Skill - Write PRD

Use this when an epic is still ambiguous enough that ticket slicing would encode assumptions too early.

## Steps

1. Read the relevant product docs and current [`../../jiraboard.md`](../../jiraboard.md) priority band.
2. State the user problem, non-goals, constraints, and success signal.
3. Keep the PRD short and link it from `docs/README.md` if it becomes a durable doc.
4. Convert approved scope into KOS-* tickets through [planTicket](planTicket.md).

## Done condition

- The user-visible problem and non-goals are clear.
- Open questions are explicit.
- Follow-up tickets can be created without guessing.
